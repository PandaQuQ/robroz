# 常见问题

这里收集刚用起来时最容易碰到的情况。安装步骤见 [安装上手](install.md)，各项设置见 [配置](configuration.md)。

## 安装脚本停下来，说 Docker 不对

脚本要 rootful Docker、默认的 socket 路径（`/var/run/docker.sock`）和 `docker compose` 插件。设了 `DOCKER_HOST`、用的是 rootless Docker，或者 socket 不在默认位置，脚本都会拒绝，并在报错里说明原因。rootless Docker 要按 [docker-host.md](../docker-host.md) 手动配。安装路径也只能用字母、数字和 `/ . _ -`。

## 客户端显示「连不上宿主」

先检查这几件事：

- host 是否还在跑。用安装脚本装的，在安装目录里看 `docker compose ps` 和 `docker compose logs -f host`
- 客户端填的地址是否指向这台 host。同一台机器上是 `http://127.0.0.1:8790`
- host 在别的机器上时，前面有没有 HTTPS 反向代理或隧道；安装脚本默认只让本机访问，见 [配置](configuration.md#从别的机器连上来)

地址下面那行浅灰小字是原因，比如「连接被拒绝」「超时」「找不到主机」。连上过一次之后再断开，已经显示的内容会留着，客户端会自己重连。

## 客户端显示「令牌被拒绝」

host 一旦设了令牌，所有访问都要带上它，本机也不例外。缺了或带错就是 401。

- 用安装脚本装的，令牌在 `~/robroz/secrets/robroz_token`，用 `cat` 看。
- 在客户端「设置 → 连接 → 地址」里重新填令牌，点「连接」。
- 如果启动客户端时设了 `ROBROZ_TOKEN`，这个值优先，表单里会写「由 ROBROZ_TOKEN 设置」，要改环境变量。客户端不读 host 的令牌文件。
- 用 curl 访问时加上 `-H "Authorization: Bearer <你的令牌>"`。

## 任务一直停在「排队」

常见原因是 Docker 没有运行，或者跑任务用的 runner 镜像不在本机。用安装脚本装的，重跑一次脚本会补拉镜像；自己构建的 host，要先 `docker build -f runner/Dockerfile -t robroz-runner:local .`，并确认 Docker 正在运行。

Docker 一时起不来时，任务可能被退回排队，等下一轮再试，看起来也会一直停在「排队」。

## 状态卡变成「没写出结果」

说明容器跑过，但没有写出结果：比如容器非正常退出、中途被删，host 或 Docker 重启了，或者一步跑得太久被取消（默认 600 秒）。这种任务已经结束，不会自动再跑，卡片上也没有「再跑一次」的按钮。要重做就再说一遍。

这和「没做成」不同：没做成也是已经结束，但写着具体原因。见 [权限和审批](permissions.md#任务结束了但活没做成)。

## bro 只是把我的话原样写回来

说明打开了测试回显（`ROBROZ_MODEL=echo`），而且还没配好一套完整的模型。在「设置 → bro → 模型」里填好地址和模型名，保存后就会改用真模型；也可以把 `compose.override.yml` 里的 `ROBROZ_MODEL: echo` 删掉。见 [配置](configuration.md#接上模型)。

## 结果是「还没设置模型」

还没接模型，也没开测试回显。点交付卡上的「去设置」，或打开「设置 → bro → 模型」，填好地址和模型名，保存后看到「能用了」就行，不用重启 host。

如果已经接了模型，状态卡却写着「没做成：模型没回」，那是模型服务没有返回可用的回答，例如超时、出错或返回了错误码。先看原因，并确认地址、模型名和密钥是对的。

## 群里没 @ 人，为什么只有一个 bro 回

从 v0.2.0 起，群里没 @ 任何 bro 的消息只由 host 挑一个 bro 回，不再每个 bro 都回一遍。想要哪个 bro 接活，就在开头 `@` 它。想恢复成每个 bro 都回，给 host 设 `ROBROZ_SINGLE_RESPONDER=0`。见 [日常使用](usage.md#在群里说话)。

## 我又说了一句，bro 没有开新任务

它手上在这个群里还有没做完的任务（排队、进行中或卡住），你这句话被追加到了那个任务上。等它做完，再说的话就会开新任务。

## bro 说「还没设置联网搜索」

搜索服务还没填，或只填了一部分（例如选了 Brave 却没有密钥）。在「设置 → bro → 联网搜索」里填好，保存后看到「能用了」就行，不用重启 host。也可以按 [搜索和 MCP](search-and-mcp.md) 用设置接口或环境变量填。

交付卡上会出现「去设置」按钮，点它打开「联网搜索」页。

## 「联网搜索」页显示「来自环境变量」，清除了也没变化

现在的设置来自 host 的环境变量。「清除」只清掉在这一页存过的设置，清不掉环境变量。想换就在这一页重新选、重新填再保存（这一页保存的优先）；想彻底去掉，就改 host 的环境变量后重启。

## SearXNG 试连失败

host 是按 JSON 去问 SearXNG 的。到你的 SearXNG 实例的 `settings.yml` 里，把 `json` 加进 `search.formats`，然后重试。地址要以 `http://` 或 `https://` 开头。

## 任务一直停在「等你批准」

去对话里找那张审批卡，点「批准」或「拒绝」。群里的卡在群里答，你和这个 bro 的私聊里那行「等你审批」的提醒点一下就能跳过去。手机上的审批卡是只读的，要到桌面端去答。卡 24 小时没人答会自动过期。详见 [权限和审批](permissions.md)。

## 写了放行规则，还是出了审批卡

自动审核判断这件事不在规则允许的范围内，卡上会写被拦的原因。没接模型、或者审核出错时，也会照常出卡等你批准。另外，新加的规则要在规则页上确认之后才生效。

## bro 没用上我配的 MCP 服务器

先看这几件事：这台服务器是不是「已连接」；是不是在这个群里打开了；host 有没有接上模型（没接模型时 bro 不会调用任何工具）；如果是 stdio 服务器，启动命令批过没有。还没批准时，任务会跳过这台服务器，不会启动进程。在「MCP」页点「连接」，看清命令后点「批准运行」。服务器连不上时任务也会照常做，只是用不到它的工具。

## 「MCP」页说「批准命令后才能加载工具」

stdio 服务器要先批准当前的启动命令和参数，host 才会去跑它。点「连接」，会展开要运行的命令和参数，看清楚后点「批准运行」；不用客户端的话调 host 的接口 `POST /api/mcp/servers/{id}/approve-command`。改过命令或参数之后要再批一次。详见 [搜索和 MCP](search-and-mcp.md)。

## 在「MCP」页删掉了一条密钥，保存后它又出现了

已经保存过的密钥，要点它旁边的「清除」，再点「保存」，才会真正删掉。那一行右边的「去掉」只是把这一行从表单里拿掉。

## 点了「去私聊接管」没有反应

这颗按钮目前还没接上，点了只会在客户端的日志里记一条。在它接好之前，需要你接手的卡住任务只能用 host 的 `POST /api/tasks/{id}/resume` 接口恢复。见 [权限和审批](permissions.md#等你批准和要去接手)。

## 客户端里找不到「建群」

现在确实还没有「建群」和「把 bro 拉进群」的按钮。最直接的开局是引入一个 bro，在私聊里说话。要多个 bro 的群，先用 host 的接口建，见 [安装上手](install.md#想要一个有多个-bro-的群)。群建好之后，改名、看成员、删群、群内搜索都能在客户端的「•••」菜单里做。

## 手机上找不到记忆、技能、例行任务

v0.2.0 的手机端设置里只有语言、外观、MCP（只读）和退出。技能、例行任务和记忆只在桌面端，手机端最早 v0.3 再做。

## 客户端去哪里下载

robroz-client 还没有发过版，目前要从源码构建，见 [安装上手](install.md#2-构建客户端)。v0.2.0 的发布说明要求配基于 `contract-v0.3.1` 或更新版本构建的客户端；v0.1.x 时随 robroz 发的旧客户端不在此列。

## 数据存在哪里，换个目录启动后对话不见了

用安装脚本装的，数据都在安装目录的 `data/` 下，重跑脚本不会动。

自己构建运行的 host，默认数据库是启动目录下的 `robroz.db`，群文件在 `./data/groups`，任务控制文件在 `./data/control`。这些相对路径按启动 host 时的当前目录计算，换个目录启动会看成一份新数据。建议每次从同一个目录启动，或把这些路径改成绝对路径。详见 [配置](configuration.md#数据放在哪里)。

## 许可证是什么

robroz 用 AGPL-3.0 开源（准确地说是 `AGPL-3.0-only`），同时由作者 PandaQuQ 另外提供商业授权。许可证原文见仓库里的 [LICENSE](../../LICENSE)，双许可的说明见 [COMMERCIAL.md](../../COMMERCIAL.md)。

## 我能拿它商用吗

能，但要看你怎么用：

- **原样用，或者愿意把改动全部公开：** 可以商用，不用找作者。条件是遵守 AGPL：保留版权和许可证声明；把软件（包括改过的版本）给别人时，要同时给出完整源码；改过的版本整体也要用 AGPL-3.0。
- **做成网上的服务也算：** 你改了 robroz，再让别人通过网络用它（比如做成在线服务、给客户用的平台），哪怕没把安装包发给任何人，也要向这些用户免费提供你改过的完整源码。这是 AGPL 第 13 条，和普通 GPL 最大的不同。
- **想闭源、不公开改动：** 比如私下改了以后做成收费产品，或者和不能公开的代码合在一起，就需要向作者买商业授权。商业授权请到 [作者的 GitHub 主页](https://github.com/PandaQuQ) 联系。

以上只是帮你理解，不是法律意见，以许可证原文为准。

## 我想贡献代码，要做什么

第一次提 PR 前，先读一遍 [CLA.md](../../CLA.md)（贡献者许可协议），然后勾选 PR 模板里的 CLA 选项（或在 PR 描述里加上 CLA.md 里那行英文声明）。CI 会检查这一项。签一次，以后的贡献都有效。你的代码著作权还是你的，只是授权作者可以把它连同整个项目一起用 AGPL 或商业条款发布。
