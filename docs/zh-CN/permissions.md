# 权限和审批

bro 不是什么都能直接做。有的事悄悄做完就行，有的事要计数，有的事必须停下来问你。这一页用日常会碰到的情况来说明。字段和接口的精确说明见英文 [permissions.md](../permissions.md)。

## bro 能做什么：三档

可以想成三档，不是三种账号。

**第一档：在这个群的工作目录里读写。** 看文件、改文件、写出结果，都直接做，不会专门通知你。做完后任务完成，对话里出现交付卡。

**第二档：出门上网。** 只允许读取（用 GET 去搜索、打开一个网页，或调用只读的 MCP 工具），而且按任务计数。默认每个任务最多 8 次，用满 8 次仍算正常；第 9 次，或用了 GET 以外的方法（比如 POST），任务就会结束，状态卡显示「没做成」，不会卡着等你。次数可以用 `ROBROZ_GET_LIMIT` 改，见 [配置](configuration.md#其他常用的-host-变量)。

**第三档：对外写入，或要填验证码。** host 不会代你填密码，也不会擅自往外发。任务会停下来等你：

- 要对外写入时，出一张审批卡，状态卡显示「等你批准」
- 要填验证码时，不出审批卡，状态卡显示「卡住」，需要你去私聊接手

MCP 工具也按这三档走：服务器声明只读的工具算第二档，计入出门次数；其它工具算第三档，用之前先出审批卡。见下面的 [bro 要用 MCP 工具时](#bro-要用-mcp-工具时)。

任务会不会停下来，只看派给它的那份说明里有没有这类步骤，跟模型中间说了什么无关。

## 审批卡

v0.2.0 的 host 只有一个令牌，你就是管理员 `local-admin`，你引入的 bro 都归你，它们的审批卡由你来批。

审批卡有三种来源：

- **bro 自己问你**：比如要删除、发送或付款之前，先出一张卡。你点「批准」或「拒绝」，只是把决定告诉它；host 不会因为你点了就自动去做那件事。
- **任务要对外写入**：host 替它出一张，摘要类似「要对外写入：要做的事」。
- **bro 要用不是只读的 MCP 工具**：摘要是「调用 服务器名.工具名」加参数摘要，见下面。

卡出在哪里，就留在哪里：

- 群里出的卡留在群里，按钮也在群里。同时你和这个 bro 的私聊里会多一行提醒「某某 在 某群 等你审批」，没有按钮，点它就跳到群里那张卡；卡答完或过期后，这行提醒也跟着变成「你已批准」「你已拒绝」或「已过期」。
- 私聊里出的卡就留在私聊里，没有额外提醒。
- v0.1 时把审批卡挪到私聊、群里只留一句提示的做法已经去掉了。

任务因为审批卡停下时：

- 状态卡变成灰色的「等你批准」，没有按钮，去答旁边那张审批卡就行
- 你批准：任务重新排队，接着做完
- 你拒绝：任务结束，那一步不执行，状态卡显示「没做成：你拒绝了 …」
- 每张卡只能答一次。答完后卡上写着谁在什么时候批准或拒绝的

答卡时客户端会带上这台设备的名字（`ROBROZ_USER_NAME`，不设就用电脑主机名），和本机名字相同就显示成「我」。你在几台电脑上都装了客户端时，在一台上答过，另一台上的同一张卡会跟着变；别给这几台设备起同一个名字。

手机端的审批卡是只读的，显示「等你批准：某某」和「到桌面上批准或拒绝」，要回到桌面端去答。

### 过期

审批卡默认 24 小时没人答就过期，按拒绝处理：卡上显示「已过期」，它拦着的任务以「没做成：审批过期了」结束。过期时间用 `ROBROZ_APPROVAL_TTL_SECS` 改。记忆、技能的确认卡和「卡住」等你接手的任务不会过期。

## 放行规则和自动审核

「设置 → bro → 放行规则」里可以写几句话，比如「允许合并 CI 全绿的 PR」。有了放行规则以后，每张审批卡先交给自动审核：host 用你接的模型对照这些规则判断这件事能不能直接放行。

- 判断可以放行：不出卡，任务直接接着做。
- 判断不能放行：照常出审批卡，卡上写着被拦的原因。
- 自动审核出错、超时，或者还没接模型：照常出卡，等你来批。它不会因为出错就默认放行。
- 一条规则都没有时，所有审批卡都照常出。

新增和删除规则本身也要确认：点「添加」或「删除」后，页面上出一张确认卡，你确认了才生效。规则的确认卡只出现在放行规则页，不会发到任何会话里。

已知问题：待确认的规则提议只在发起它的那次打开的规则页里显示，关掉页面再打开就看不到了，到期照常过期。v0.3 会改成打开规则页时显示待确认的提议。

## 用命令拉起 MCP 服务器时，要先批准命令

用命令拉起来的（stdio）MCP 服务器，填写的启动命令和参数必须先由你批准，host 才会去跑这条命令。还没批准时，试连和列出工具都不会启动进程，任务要用这台服务器时也会跳过它。改了命令或参数之后，批准会作废，要再批一次。用 HTTP 访问的服务器不需要这项批准。

在客户端的「MCP」页里批准：还没批准的服务器下面那行灰字是「批准命令后才能加载工具」。点「连接」或保存这台服务器时，会展开一块批准区，把要运行的命令和每个参数一行一行列出来，并提醒「这条命令会在你的电脑上运行」。

- 看清楚命令和参数，确认是你信得过的，再点「批准运行」。批准后会自动试连一次，成功时显示「能用了 · 几个工具」。
- 不确定就点「取消」，什么也不会运行。

这和审批卡不是一回事：审批卡是 bro 在任务里想做某件事时问你；命令批准是你登记服务器时，决定能不能在这台机器上跑这条命令。更多见 [搜索和 MCP](search-and-mcp.md)。

## bro 要用 MCP 工具时

bro 想用一个不是只读的 MCP 工具时，host 先停下任务，出一张审批卡，写明要调用哪台服务器的哪个工具、带什么参数。状态卡显示「等你批准」，下面一行写「在用 服务器名.工具名」。

- 你批准：任务接着跑，真的去调用这个工具，把结果交给 bro 继续回答。这一次也算一次出门上网。
- 你拒绝：不调用，任务结束，交付卡写「未执行」，状态卡显示「没做成：你拒绝了 服务器名.工具名」。
- 这种卡只能在卡上答，不能用恢复卡住任务的接口（resume）放行，那样会被拒绝。

## 等你批准，和要去接手

任务停下来等人时，状态卡上的那句话不一样，处理方式也不一样。

- **等你批准**：已经有一张对应的审批卡。灰色，没有按钮，去答那张卡即可。
- **卡住**：没有这样的审批卡，典型情况是要填验证码。琥珀色，带「去私聊接管」。按设计，你应该到和这个 bro 的私聊里接手，再让任务继续。

「去私聊接管」这颗按钮目前还没接上，点了只会在客户端的日志里记一条，不会真的打开私聊，也不能从界面里恢复任务。在它接好之前，这类任务只能用 host 的 `POST /api/tasks/{id}/resume` 接口恢复，见 [api.md](../api.md#post-apitasksidresume)。

## 任务结束了，但活没做成

有时任务已经结束，但活并没有做成。这时不会出现绿色的「完成」，而是灰色的「没做成：原因」，没有按钮。常见的有：

| 情况 | 状态卡上的原因 | 有没有交付卡 |
| --- | --- | --- |
| 模型没有回答（超时、出错、返回错误码） | 模型没回，可能带上 HTTP 状态码 | 有，结果里也写着这句 |
| 你拒绝了任务的审批卡 | 你拒绝了 … | 没有 |
| 你拒绝了 MCP 工具的审批卡 | 你拒绝了 服务器名.工具名 | 有，摘要是「未执行」 |
| 出门次数用超了 | 出网请求超额，带上「已用/上限」 | 没有 |
| 出门用了 GET 以外的方法 | 只允许 GET，这次用了 POST | 没有 |
| 模型和工具来回的轮数到上限（默认 8 轮） | 工具调用轮数到上限了 | 有 |
| 审批卡过期 | 审批过期了 | 没有 |

还有一种是「没写出结果」：容器跑过，但非正常退出、没写出结果，或中途消失了（比如 host 或 Docker 重启），也可能是一步跑得太久被取消（`ROBROZ_STEP_TIMEOUT_SECS`，默认 600 秒）。它同样已经结束、不会自动再跑，卡上直接显示「没写出结果」，不带「没做成：」前缀，也没有交付卡。

> 截图待补：状态卡显示灰色「没做成：你拒绝了 …」，没有交付卡。
