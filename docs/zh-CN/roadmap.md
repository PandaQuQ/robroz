# 路线图

这一页是给人看的摘要：v0.2.0 已经有什么，v0.3 打算做什么，以及更往后的方向。更细的条目、依赖和接口打算，见 [第二期路线图](../roadmap-phase2.md)（那份文件的条目表没有按 v0.2 / v0.3 重排，以这里和 README 的「状态」一节为准）。具体顺序以仓库里的 issue 和 PR 为准。

## v0.2.0 已经有的

私有化部署、Docker 一条命令安装、群和私聊、派任务、状态卡（带准确计时）和交付卡、追加、群里没 @ 人时只由一个 bro 回、bro 头像、群资料和成员列表、改群名、删群、群内搜索、三级权限、审批卡、放行规则和自动审核、选项卡、例行任务的列表和暂停、未读、断线后能补上卡片的实时推送、记忆和技能、联网搜索，以及 MCP：配置服务器、列工具、按群打开，bro 能调用工具，不是只读的工具要先过审批卡，stdio 服务器的进程在任务之间常驻。

客户端是 Windows、Linux、macOS 上的原生桌面程序；手机端是 Slint 写的试验版。

还没有：客户端发布版（目前要从源码构建）、网页版、文件树、终端、桌面流、Webhook、多用户账号。长会话复用同一个容器原本在 v0.2 的范围里，但没有进 v0.2.0。

## v0.3 打算做的

- **多用户账号**：每个用户有自己的令牌，群、bro 和任务按用户隔离。
- **分层记忆**：常驻一份短笔记，其余记忆按相关度召回。
- **派活树**：一个任务可以拆给别的 bro 去做，子任务都交回来之后，上游任务才算完成。
- **会话级审批档位**：按会话设定审批的松紧，以及回合中途向你提问、答完接着跑。
- **放行规则页**：打开时显示还没确认的规则提议。
- **手机端**：最早从 v0.3 起补上技能、例行任务和记忆。

## 更往后的

大致分几条线往前推，做完再排更后面的项。

**把现在已有的能力做完整：**

- 记忆和技能的更完整形态，例如按项目留下可以打开、可以撤销的工作记录
- 搜索时在对话里展示「正在搜网页 / 正在读页面」，并注明出处链接
- 把常用应用通过 MCP 接到 bro 上的完整形态：由你完成授权（OAuth），并按 bro 授予范围
- 例行任务补上运行历史、立刻跑一次、在界面里新建和编辑；现在客户端只能看列表、暂停和恢复
- 「没写出结果」的任务，由你决定要不要再跑一次；现在这张卡没有按钮，也不会自动重跑
- 接好「去私聊接管」，让卡住的任务能在界面里接手和恢复
- 收件箱、仓库或已连接的应用有约定变化时再叫醒 bro（Webhook 和事件触发）

**组织方式和运行处：**

- 按工作、日常、项目分成频道或房间，带各自的说明、目录和规则
- 每个 bro 可以有自己的运行处，而不只是「一个群共用一个目录」
- bro 要往外发的邮件或消息，先出一张草稿卡，由你点了才发送

**更多的使用入口：**

- 客户端里直接建群、把 bro 拉进群
- 桌面三个系统上更接近各自系统风格的外观
- 网页版
- 手机端做完整，在安卓和 iOS 真机上测过再发布
- 把 bro 当联系人来管理：置顶、暂停和恢复
- 群里多个 bro 之间的分工和交接

更靠后的还有：用量查看和上限、整队导入与分享、看它的桌面或浏览器并在需要时接手、文件树和终端、可发布的预览页等。这些都排在前面那些做完之后。

## 还没定的

- 客户端首个发布版什么时候发
- 长会话复用同一个容器排在哪个版本
- 不会把现在的执行器默认换成别的命令行工具
- 域名买不买，不在这份路线图里
