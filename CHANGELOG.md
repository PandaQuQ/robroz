## [0.2.0] - unreleased

### Added

- `deploy/install.sh --no-pull` skips pulling images, and a run without that flag also skips the pull when the host and runner images for the pinned tag are already on the machine (`docker image inspect`). The host image has a `HEALTHCHECK` that runs `robroz-host --health`, which treats HTTP 401 or 200 on `GET /api/bros` as alive (no new endpoint, no curl in the image). See [docs/install.md](docs/install.md#one-command-install-docker).
- Live stream replay from a change log: every write to a card table (`messages`, `tasks`, `deliveries`, `choices`, `approvals`, and `memories` / `skills` behind confirm cards) appends a row to `group_changes` through SQLite triggers, including the owner's DM `approval_reminder` and the group a moved card came from. The SSE `id:` is now that row's `seq`, an opaque decimal cursor that follows commit order instead of the wall clock, so a reconnect can no longer skip a card stamped earlier than the client's last id. Only the last frame of a batch carries the `id:`, so a drop mid-batch replays the whole batch. RFC 3339 ids from older hosts still resume by time. Each poll reads only the group's log and rebuilds only the changed cards. Once an hour the log is compacted to the newest row per card and rows older than `ROBROZ_EVENT_RETENTION_HOURS` (default 168) are dropped; a reconnect from before that gets a full snapshot. Migration: `group_changes`, `event_log_meta`, the triggers, and `group_id` indexes on `messages`, `tasks`, `deliveries`, `choices` and `approvals`; no backfill. No contract change. See [docs/api.md](docs/api.md#get-apigroupsidstream).
- Bounds for long-lived streams and noisy progress (no contract change): the bro's own progress lines are written at most once per `ROBROZ_PROGRESS_MIN_MS` (default 1000) per task, with the newest held line written by the pump once the gap has passed; coded progress is immediate. `/stream` reads `ROBROZ_SSE_POLL_MS` (250), `ROBROZ_SSE_KEEPALIVE_SECS` (15), `ROBROZ_SSE_MAX_AGE_SECS` (3600, then a clean close; reconnect with `Last-Event-ID`) and `ROBROZ_SSE_MAX_STREAMS` (64; one more gets 503 `too_many_streams` with `Retry-After: 5`), and sends `X-Accel-Buffering: no`. The tool round limit is now `ROBROZ_MAX_TOOL_ROUNDS` (default 8). Zero, empty or invalid values keep the defaults, as for the Watchdog. See [docs/configuration.md](docs/configuration.md).
- One-command install, `deploy/install.sh`: checks docker and `docker compose`, writes `compose.yml`, a placeholder `.env` and a locally generated token into `~/robroz` (or `ROBROZ_DIR`), pulls the pinned host and runner images and runs `docker compose up -d`. A rerun upgrades and never overwrites `.env`, the token or `data/`. `--dry-run` and `--no-start` write or start nothing. `deploy/compose.host.yml` now reads optional `ROBROZ_DATA`, `ROBROZ_BIND` and `ROBROZ_PORT` (defaults `127.0.0.1:8790`). The token is mode 0640, owned by the installing user, group the container's gid (read from the host image; not hard-coded as uid 1000). Rootless or a non-default socket is refused, with the reason and a link to [docs/docker-host.md](https://github.com/PandaQuQ/robroz/blob/main/docs/docker-host.md#security-dockersock-is-root-on-this-machine). `DEFAULT_VERSION` stays pinned (override with `ROBROZ_VERSION`); a tag push fails if the pin or the compose tags do not match the tag, so they are bumped in a PR before release rather than written to main by the workflow. CI runs shellcheck, a dry run and a no-start rerun on the script. See [docs/install.md](docs/install.md#one-command-install-docker).

- Codes for card progress, approval reasons and Watchdog hints (#180). Additive and optional: `status` events get `progressCode` and `progressParams` (`tool`, `step`, `steps`, `minutes`, `text`), and `approval` events get `reasonCode`. The Chinese `progress` and `reason` text is unchanged. Stored approval reasons are coded once on upgrade. See [docs/api.md](docs/api.md#progress).
- Single responder (v0.2): a group message that names nobody now gets one answering bro instead of a turn for every bro. The bro is the one already waiting on the person (an open task or an unanswered choice card), else the only bro in the group, else the one the configured model picks from bro names and profiles (strict JSON `{"bro":"<id>"}`, 5 second limit, `max_tokens` 48), else the bro that answered last, else the first who joined. The picked bro is handled like an `@name` bro (visible task, `Said.task`, follow-up joins its open task); a reply wakes another bro only by a leading `@name`. `@name` messages and DMs are unchanged. `ROBROZ_SINGLE_RESPONDER=0` restores every-bro turns. Migration: additive `turns.single` column (default 0). No contract change. `OpenAiCompat::with_max_tokens` is new in `robroz-model`. See [docs/design/multi-agent.md](docs/design/multi-agent.md#single-responder).
- Optional bro avatar: `Bro.avatar` `{"shape": 0–11, "color": 0–9}` (`robroz_contract::BroAvatar`), indices into the client's own shapes and palette. Set on `POST /api/bros`, set or cleared (`null`) on `PATCH /api/bros/{id}` (owner only; an absent field is unchanged). Out of range is 400 `invalid_avatar`. Omitted when unset, so older JSON is unchanged. New contract types `BroAvatar` and `PatchBro`; `RenameBro` still works. See [docs/api.md](docs/api.md#bro-avatar).

- Group members, rename, delete and search (**contract change, needs a new `contract-v*` tag**): `Group.createdBy`, always-serialized `Group.dm` (true for a bro DM; clients hide rename/delete unless `!group.dm && (me.role == admin || group.createdBy == me.userId)`), `GET /api/groups/{id}/members`, `PATCH /api/groups/{id}`, `DELETE /api/groups/{id}` and `GET /api/groups/{id}/search?q=&limit=` (SQLite FTS5, trigram), with the error codes `not_group_creator`, `not_group_member` and `group_is_dm`. Migration: nullable `groups.created_by` (older groups are admin-only), `group_tombstones`, `container_reaps`, and the `messages_fts` index with triggers, built from existing messages once. See [docs/api.md](docs/api.md#who-may-do-what-in-a-group).
- `robroz-host --version` (and `-V`) prints `robroz-host <version> (<short git sha>)` and exits 0 without a token, database or Docker. Release builds are stripped (`[profile.release] strip = true`) for both the tarball and the images, and CI builds the host image and runs `--version` in it.

- Host Docker image and compose example ([#170](https://github.com/PandaQuQ/robroz/pull/170)): `host/Dockerfile` (`debian:bookworm-slim`, Docker CLI, no Node), `deploy/compose.host.yml`, and [docs/docker-host.md](docs/docker-host.md). The host binary release is unchanged.
- Release builds push `ghcr.io/pandaquq/robroz-host:<tag>` next to the runner image ([#171](https://github.com/PandaQuQ/robroz/pull/171)): linux/amd64 only, version tags only, no `latest` tag.
- Bro owners and owner-only approvals (v0.2 accounts, first part): a `users` table with a bootstrap admin (the env token and no-token loopback act as it), `GET /api/me`, `Bro.ownerUserId`, one DM per (user, bro), `ownerUserId` / `ownerName` on approval cards, and `authorUserId` / `authorName` on `message` events. Approval cards stay in the group they were raised in; the owner's DM gets a new `approval_reminder` event. See [docs/permissions.md](docs/permissions.md) ([#174](https://github.com/PandaQuQ/robroz/pull/174)).
- Desktop client: only a bro's owner sees Approve and Deny on a group approval card; everyone else sees a read-only status line. The owner's DM shows a reminder row that opens the card in its group ([#177](https://github.com/PandaQuQ/robroz/pull/177)).
- Mobile client spike for Android and iOS, built with Slint (`mobile/`): connect, chat list, one chat with status cards, and settings. Not yet tested on a real device; CI builds an APK and an unsigned `.ipa` ([#156](https://github.com/PandaQuQ/robroz/pull/156)).
- Stable machine codes for what the host used to send only as Chinese text, so the host no longer depends on `robroz-card` and that crate can move to the client repo. Additive: no field is removed or changed. `status` events get `statusCode` (`queued` / `running` / `blocked` / `done` / `no_result`), `failureCode` and `failureDetail` (the raw reason without a prefix, so the client adds exactly one 「没做成：」); `delivery` events get `badge` (`briefing`), `failureCode` and `failureDetail`. Every 4xx/5xx JSON error body has a `code` (`robroz_contract::error_codes`); `error` and `message` are for logs only. The legacy Chinese card copy moved to `robroz_contract::legacy` (deprecated). See [docs/api.md](docs/api.md#error-codes-v02) ([#178](https://github.com/PandaQuQ/robroz/pull/178)).

### Changed

- The `robroz-host` package version is `0.2.0`. `deploy/install.sh` sets the data directory to mode 0700 (owned by the container user) and the database file to mode 0600, and a rerun tightens an older install. The host process uses umask 0077 and tightens the mode of an existing database when it opens it, so a newly created database is also 0600.
- `failureDetail` carries only language-neutral raw data: the HTTP status code (`401`, not 「模型服务返回 401」), a tool name, a method, `used/limit`, raw upstream or OS error text, or a snake_case reason token. The host stores each failure typed (`robroz_contract::FailureData`) in a new `failure_data` column on `tasks` and `deliveries` and no longer parses its own Chinese text to build events; older rows are backfilled once at startup. `failure` is unchanged ([#181](https://github.com/PandaQuQ/robroz/issues/181)).
- Requests rejected before a handler runs (invalid JSON, a missing field, an unknown enum value, a wrong `Content-Type`, a path or query that does not parse) now get the standard JSON error body with a stable `code` (`invalid_json`, `missing_field`, `invalid_enum`, `unknown_field`, `invalid_field`, `unsupported_media_type`, `body_too_large`, `invalid_body`, `invalid_path`, `invalid_query`) instead of axum's plain text. HTTP statuses are unchanged ([#179](https://github.com/PandaQuQ/robroz/issues/179)).
- Pooled stdio MCP processes are keyed by server id, config hash and `group_id`, so two groups (or a group and a bro DM) never share a process ([#190](https://github.com/PandaQuQ/robroz/pull/190)). `PATCH` or `DELETE` of a server still stops every per-group process for that server. See [docs/search-and-mcp.md](docs/search-and-mcp.md#stdio-连接池). No contract changes.
- Stdio MCP servers stay running between tasks instead of being started for every `tools/list` and `tools/call` ([#188](https://github.com/PandaQuQ/robroz/pull/188)). The host keeps one process per server, keyed by the server id and a hash of its command, args and env, so editing a server or rotating a key starts a new process. The tool list is cached for the life of a process. A process that exited or broke its pipe is replaced on next use (`tools/list` retries once; `tools/call` never retries). Idle processes are stopped after `ROBROZ_MCP_IDLE_SECS` (default 600; `0` turns the pool off), each process takes at most `ROBROZ_MCP_MAX_IN_FLIGHT` requests at a time (default 4), and the 10-second limit still applies to each request. Editing or deleting a server stops its process at once, and the host stops all of them on SIGTERM or Ctrl-C. Approval, metering and secret handling are unchanged; HTTP servers and the `GET …/tools` and `POST …/test` routes are not pooled. See [docs/search-and-mcp.md](docs/search-and-mcp.md#stdio-连接池). No contract changes.
- `POST /api/approvals/{id}/approve` and `/deny` return 403 `{"code":"approval_forbidden","reason":"not_owner"|"decided"|"expired"}` instead of 409 for an answered or expired card, and for a caller who is not the bro's owner. Renaming a bro, opening its DM or adding it to a group by someone else is 403 `not_bro_owner`. `GET /api/bros` lists the caller's bros. The host no longer writes 「已发到主人私聊」 ([#174](https://github.com/PandaQuQ/robroz/pull/174)).

## [0.1.1] - 2026-11-25

Published as a pre-release.

### Changed

- Release notes are written in English and Chinese, from `.github/release-notes/<tag>.md` or a template, and `v0.*` releases are marked as pre-releases ([#166](https://github.com/PandaQuQ/robroz/pull/166)).

### Fixed

- The Linux client's X11 window icon (`_NET_WM_ICON`) is now 128×128 instead of 512×512, so window managers and taskbars that use it show the robroz icon instead of a generic one. The 512×512 property was about 1 MiB, larger than many X11 clients read ([#167](https://github.com/PandaQuQ/robroz/pull/167)).
- The Windows client no longer opens an extra command-line window on start ([#165](https://github.com/PandaQuQ/robroz/pull/165)). Release builds use the Windows GUI subsystem. Debug builds keep the console. When the client is started from Explorer, stderr output such as a failed preference save or a panic message is not shown; start it from a shell to see it.

## [0.1.0] - 2026-11-25

Published as a pre-release. First release of robroz: a single-user, self-hosted multi-agent workspace with a Rust host and a native desktop client.

### Added

- Window icon for the desktop client, and a Windows exe icon ([#150](https://github.com/PandaQuQ/robroz/pull/150)).
- App icons in release packages ([#161](https://github.com/PandaQuQ/robroz/pull/161)): `robroz.app` ships `icon.icns` (`CFBundleIconFile`); the Linux client tarball ships `robroz.desktop` and `robroz.png`. The same PR adds a `workflow_dispatch` dry run: it builds and packages the binaries, and builds the runner image without pushing it or logging in to GHCR. It does not create a release.
- Release packaging when a `v*` tag is pushed ([#149](https://github.com/PandaQuQ/robroz/pull/149)): draft GitHub Release assets, unsigned, with `SHA256SUMS.txt`. Client archives are Linux x86_64 (`.tar.gz`), Windows x86_64 (`.zip` with the `.exe`), and macOS aarch64 only (`.zip` containing `robroz.app`). The host ships for Linux x86_64 only. Intel Macs are not covered.
- Runner image `ghcr.io/pandaquq/robroz-runner:<tag>` on `v*` tags ([#151](https://github.com/PandaQuQ/robroz/pull/151)): `linux/amd64` only, tagged with the git tag, no `latest` tag. Example: `ROBROZ_IMAGE=ghcr.io/pandaquq/robroz-runner:v0.1.0`.
- Manual platform screenshot workflow for Windows and macOS ([#153](https://github.com/PandaQuQ/robroz/pull/153), [#154](https://github.com/PandaQuQ/robroz/pull/154)).
- Client HTTPS via rustls, and persisted connection settings ([#152](https://github.com/PandaQuQ/robroz/pull/152)). The host address is stored in a `host` file next to `lang`. The token is stored in the OS keyring (macOS Keychain, Windows Credential Manager, Secret Service on Linux), falling back to a `token` file next to `lang` with mode `0600` on Unix. `ROBROZ_HOST` and `ROBROZ_TOKEN` override saved values for the current run and are never written back.
- In-app connection form with Host, Token, and Connect, on the offline pane and in Settings ([#159](https://github.com/PandaQuQ/robroz/pull/159)). A field set by the environment is read-only (`Set by ROBROZ_HOST` / `Set by ROBROZ_TOKEN`). When both are set by the environment, Connect is disabled. A non-local `http://` host shows `Unencrypted. Use HTTPS for remote hosts.` A 401 is titled `Token rejected` (「令牌被拒绝」), with the reason `The host rejected the token. Check ROBROZ_TOKEN.` An unreachable host is titled `Can't reach the host` (「连不上宿主」); the reason line is `Can't reach host.` (「连不上宿主。」) plus the detail.
- Chat feed rendered as bubbles ([#155](https://github.com/PandaQuQ/robroz/pull/155)). Your messages sit on the right; bro status, approval, choice, and confirm cards sit on the left. A delivery with `bot_name` is attached to that bro and follows the usual 2-minute grouping; a delivery without `bot_name` stands alone, with no avatar or name. On macOS the UI font is Hiragino Sans GB; on Windows it is Microsoft YaHei UI.
- Optional `taskId`, `botId`, and `botName` on `Event::Delivery` ([#158](https://github.com/PandaQuQ/robroz/pull/158)). The fields are omitted when absent, so older JSON serializes unchanged.
- Appearance setting ([#160](https://github.com/PandaQuQ/robroz/pull/160)): a Settings row Appearance / 「外观」 under Language, also on the Can't reach the host page, with System / 「跟随系统」, Light / 「浅色」, and Dark / 「深色」. The default is System, which follows the OS live (`iced::system::theme_changes()`). The choice is saved as one line (`system`, `light`, or `dark`) in a `theme` file next to `lang`; no file means System. The footer Dark toggle is removed. `ROBROZ_THEME=light|dark` is honoured only in fake and gallery runs; a fake run with no variable defaults to Light.

### Fixed

- Dark-mode segmented controls show the selected option more clearly ([#162](https://github.com/PandaQuQ/robroz/pull/162)).
- Linux release builds run on older distributions ([#164](https://github.com/PandaQuQ/robroz/pull/164)). They are built on Ubuntu 22.04, and the release job fails if a binary needs glibc newer than 2.35. The client needs glibc 2.35 or newer; the host needs 2.34 or newer. The Linux icon is renamed to `robroz.png` to match `Icon=robroz` in `robroz.desktop`.

### Known issues

- Windows: an extra command-line window opens when the client starts. Leave it open; closing it also quits the client. Fixed in the next release.
